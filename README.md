# 正反方博弈决策 Skill

## 1. 简介

`dialectic-decision` 是一个用于重要问题、方案或决策压测的 Codex Skill。

当用户明确要求“正反方博弈”“对抗分析”“20 轮推演”“两个 agent 较量”等分析方式时，该 Skill 会组织正方与反方进行内部交锋，再由仲裁者输出一个精简、可执行的最终建议。

## 2. 适用场景

适合用于：

- 产品方案决策
- 需求优先级判断
- 商业策略选择
- 技术方案取舍
- 重要文档定稿前审查
- 风险较高、影响较大的问题
- 用户希望通过反方质疑获得更稳妥方案的场景

不适合用于：

- 简单事实查询
- 明确的小型执行任务
- 用户只要求快速回答的问题
- 信息严重不足且无法判断边界的问题
- 不需要深度推演的日常讨论

## 3. 触发方式

该 Skill 采用显式触发，不会默认用于所有问题。

可以使用类似表达触发：

- 调用正反方博弈 Skill
- 用博弈方式分析
- 正反方辩论一下
- 让两个 agent 较量
- 做 20 轮推演
- 用反方质疑后给最佳方案
- Use `$dialectic-decision`

## 4. 工作机制

Skill 使用三个角色：

| 角色 | 职责 |
|---|---|
| 正方 Agent | 提出并强化方案，论证价值、收益、可行性和执行路径 |
| 反方 Agent | 攻击假设、风险、成本、失败场景和遗漏点 |
| 仲裁者 | 综合双方观点，形成最终可执行建议 |

默认情况下，Skill 会进行 20 轮内部博弈，并维护一份私有轮次台账。最终不会展示完整 20 轮过程，只输出精简结论。

## 5. 默认输出格式

```markdown
## 最佳方案

[直接给出推荐方案]

## 核心理由

- [理由 1]
- [理由 2]
- [理由 3]

## 主要风险

- [风险 1]
- [风险 2]

## 修正建议

- [建议 1]
- [建议 2]

## 最终判断

[一句话结论：建议做 / 不建议做 / 建议调整后做]
```

## 6. 使用示例

```text
调用正反方博弈 Skill，帮我分析：我们是否应该优先做 App 首页改版，而不是先做消息中心优化？
```

```text
用 20 轮正反方推演一下：这个需求是否值得进入下个版本？
```

```text
Use $dialectic-decision to pressure-test this product strategy and give a concise final recommendation.
```

## 7. 注意事项

- 不会自动用于普通问题，必须显式触发。
- 默认不展示完整 20 轮辩论过程。
- 如果背景、目标、约束或成功标准缺失，应该先补充信息。
- 最终输出必须给出明确判断，不能只罗列正反观点。
- 如果真实子 agent 不可用，可以降级为内部模拟，并在输出中说明。
