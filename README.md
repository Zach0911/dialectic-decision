# 正反方博弈决策 Skill

## 1. 简介

`dialectic-decision` 是一个用于重要问题、方案或决策压测的 Codex Skill。

当用户明确要求“正反方博弈”“对抗分析”“20 轮推演”“两个 agent 较量”等分析方式时，该 Skill 会组织正方与反方进行内部交锋，再由仲裁者输出一个精简、可执行的最终建议。

## 2. 适用场景

适合用于：

- 产品方案决策
- 需求优先级判断
- 商业策略选择
- 技术方案取舍
- 金融投资判断
- 重要文档定稿前审查
- 风险较高、影响较大的问题
- 用户希望通过反方质疑获得更稳妥方案的场景

不适合用于：

- 简单事实查询
- 明确的小型执行任务
- 用户只要求快速回答的问题
- 信息严重不足且无法判断边界的问题
- 不需要深度推演的日常讨论
- 缺少关键行情、风险偏好、仓位或周期信息的投资结论

## 3. 触发方式

该 Skill 采用显式触发，不会默认用于所有问题。

可以使用类似表达触发：

- 调用正反方博弈 Skill
- 用博弈方式分析
- 正反方辩论一下
- 让两个 agent 较量
- 做 20 轮推演
- 用反方质疑后给最佳方案
- 用正反方博弈判断这个投资
- 帮我压测是否买入/卖出/加仓/减仓
- Use `$dialectic-decision`

## 4. 工作机制

Skill 使用三个角色：

| 角色 | 职责 |
|---|---|
| 正方 Agent | 提出并强化方案，论证价值、收益、可行性和执行路径 |
| 反方 Agent | 攻击假设、风险、成本、失败场景和遗漏点 |
| 仲裁者 | 综合双方观点，形成最终可执行建议 |

默认情况下，Skill 会进行 20 轮内部博弈，并维护一份私有轮次台账。最终不会展示完整 20 轮过程，只输出精简结论。

20 轮默认拆成 4 个阶段：

| 轮次 | 目标 |
|---|---|
| 1-5 | 明确最强主张、目标、关键假设和成功标准 |
| 6-10 | 攻击风险、隐藏成本、失败场景和缺失信息 |
| 11-15 | 修正方案，加入约束、缓释措施、仓位或备用路径 |
| 16-20 | 仲裁收敛，确定最终标签、条件和输出 |

如果用户要求查看过程，默认只展示阶段摘要，不展示完整隐藏推理全文。

## 5. 金融投资判断模式

当问题涉及股票、债券、基金、ETF、加密资产、期权、期货、IPO、组合配置、买入/卖出/持有、加仓/减仓等投资判断时，Skill 会进入金融投资判断模式。

### 5.1 前置确认

投资场景需要优先确认：

- 标的：代码、名称、市场、资产类别
- 决策：买入、卖出、持有、加仓、减仓、认购、规避或对比
- 周期：短线、中线、长线或未知
- 用户情况：风险承受能力、已有仓位、组合集中度、可承受亏损、流动性需求
- 数据基础：最新价格、估值、财务、公告、新闻、宏观与行业背景

如果判断依赖最新行情或公告，必须先核查最新数据；如果无法核查，需要说明限制，不能假装数据是最新的。

如果关键信息缺失，Skill 会优先追问：

```markdown
请先补充 4 个信息：

1. 标的：代码 / 市场 / 资产类型
2. 周期：短线 / 中线 / 长线
3. 仓位：无仓 / 轻仓 / 重仓 / 占总资产比例
4. 风险：最大可接受亏损比例或金额
```

### 5.2 数据时效规则

涉及当前价格、估值、公告、新闻、政策、利率、财报、资金流或市场状态时，必须先核查最新数据，并在输出中说明数据时间基础。

如果无法核查当前数据，不能给行动性结论，只能输出“信息不足”或框架分析。

### 5.3 投资品类检查

| 品类 | 必查重点 |
|---|---|
| 股票 | 商业质量、估值、财报、指引、资产负债、治理、流动性、事件风险 |
| ETF/基金 | 指数或策略、持仓集中度、费率、跟踪误差、流动性、溢折价、回撤 |
| 债券 | 信用风险、久期、收益率、利率敏感性、发行人质量、违约风险 |
| 期权/期货 | 杠杆、保证金、到期日、隐含波动率、流动性、爆仓风险 |
| IPO | 估值、基石/禁售、认购热度、基本面、上市波动 |
| 加密资产 | 托管、流动性、波动率、协议/交易所/监管风险、杠杆 |

### 5.4 投资输出格式

```markdown
## 投资判断

[信息不足 / 不建议参与 / 谨慎观察 / 低仓位试错 / 分批参与 / 持有但设退出条件 / 减仓控制风险]

## 关键依据

- [依据 1]
- [依据 2]
- [依据 3]

## 反方最强质疑

- [质疑 1]
- [质疑 2]

## 主要风险

- [风险 1]
- [风险 2]

## 仓位与风控

- 仓位：[建议区间或信息不足]
- 失效条件：[什么发生时原判断失效]
- 退出/复盘条件：[止损、止盈、事件、财报、价格区间或时间点]

## 最终结论

[一句话：在什么前提下，可以/不可以/谨慎参与]
```

### 5.5 投资判断边界

- 不承诺收益。
- 不使用“稳赚”“必涨”“无风险”等表达。
- 不在缺少风险偏好、周期、仓位信息时直接给强结论。
- 不把“买入 / 卖出”作为单独结论，必须附带前提、仓位、失效条件和复盘条件。
- 必须包含风险、仓位、失效条件和退出/复盘条件。
- 优先使用“信息不足 / 谨慎观察 / 低仓位试错 / 分批参与 / 减仓控制风险”等判断标签。

## 8. 注意事项

- 不会自动用于普通问题，必须显式触发。
- 默认不展示完整 20 轮辩论过程。
- 如果背景、目标、约束或成功标准缺失，应该先补充信息。
- 最终输出必须给出明确判断，不能只罗列正反观点。
- 如果真实子 agent 不可用，可以降级为内部模拟，并在输出中说明。
- 涉及投资判断时，必须处理数据时效、风险偏好、仓位、失效条件和退出/复盘条件。
